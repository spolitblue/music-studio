## 一、为什么要有这份文档

现在的玻璃效果**在功能上是对的，但算力方向错了**。

我（上一个会话）用 CPU + numpy 做了完整的物理模拟：
圆角矩形有符号距离场（SDF）→ 梯度求边缘法线 → 折射位移图 → 双线性重映射
→ 凝霜 → 表面起伏场 → 边缘聚光。单块面板 **12~30 ms**，9 块面板首帧约 340ms，
拖动时不得不节流到 80ms（12fps）。

**用户指出这个效果完全可以实时做到**，并给了一个参考实现：本地安装的
`InfiniteGUI Client`（.NET + WebView2 桌面应用）。

### 参考实现到底怎么做的（我反编译它的 DLL 确认过）

`C:\Users\LZY20\AppData\Local\InfiniteGUI Client\current\InfiniteGUI.Client.dll`
（2.5MB，前端资源内嵌在里面）中的原文：

```css
.hud-chip {
  min-width: 120px;
  padding: 10px 12px;
  border: 1px solid rgba(148, 163, 184, 0.22);   /* 1px 亮边 */
  border-radius: 8px;
  background: rgba(15, 23, 42, 0.28);            /* 半透明暗底 */
  color: rgba(248, 250, 252, 0.82);
  font-family: Consolas, "Cascadia Mono", monospace;
  font-size: 13px;
  font-weight: 600;
  line-height: 1.15;
  box-shadow: inset 0 1px 0 rgba(255, 255, 255, 0.06);  /* 顶部内高光 */
  backdrop-filter: blur(3px);                     /* ← 全部的秘密 */
  white-space: nowrap;
}
```

**它没有 SDF、没有位移贴图、没有着色器。就 `blur(3px)` 一行。**
字符串扫描结果：`backdrop-filter` 命中 1 次，`feDisplacementMap` / `wgsl` /
`navigator.gpu` / `glsl` **全部 0 命中**。

它之所以实时，是因为 `backdrop-filter` 是**浏览器合成器层面的效果** ——
GPU 免费代劳，页面代码一行都不算。

### 结论

效果好不好，关键在**背景够不够有细节** + **高光和边框做没做对**，
不在那堆额外计算上。我加的折射/起伏/凝霜，把"一行 CSS"变成了"30 毫秒 CPU"。

## 二、本次任务

**目标：玻璃在交互路径上必须实时（60fps 无节流），且观感不退化。**

### 必须做到

1. **引入"合成器层"概念**。这是整个方案的关键洞察：

   我们的窗口背景**已经被 Windows DWM 亚克力模糊过了**（真实桌面背景）。
   所以**坐在窗口背景之上的面板，根本不需要自己再做模糊** ——
   直接画半透明染色 + 亮边 + 顶部高光，让 DWM 的模糊透上来即可。
   这正是 `backdrop-filter` 在浏览器里"免费"的原因，我们同样可以免费拿到。

   于是面板分两类：
   * **A 类 · 坐在窗口背景上**（侧边栏、走带条、母带卡、工程头）
     → 零 CPU，直接绘制。**这类占绝大多数。**
   * **B 类 · 坐在应用自己的内容上**（覆盖在轨道列表 / 音序器网格之上的浮层）
     → 需要模糊"我们自己的画面"。用**降采样快照**：只取 1/4 分辨率、
       内容变化时才重算，且模糊本身就掩盖了低分辨率。

2. **交互路径上不许有 30ms 级的同步计算**。验收标准：
   * 拖动窗口时面板随每帧刷新（不再 80ms 节流）
   * 单帧 GUI 占用 < 16ms（目标 60fps）
   * 首帧总耗时 < 200ms（当前约 340ms，且拖动时会重复付）

3. **观感不许退化**。现有的设计语言是硬约束（见 `app/theme.py`）：
   三层材质台阶、顶部高光边、粗亮轮廓、光面/磨砂可切换（`theme.finish`）。
   改完之后**截图对比**，确认玻璃仍像玻璃。

4. **选项化，而不是删掉**。现有的高质量路径（SDF 折射）**保留但默认关闭**，
   作为"高质量模式"（例如截图导出、静止时后台补算并平滑替换）。
   理由：它确实更真实，只是不该在交互路径上跑。若你论证它没有保留价值，可以删 ——
   但要说明理由。

5. **不引入 Chromium**。不要为了 `backdrop-filter` 去加 QtWebEngine
   （约 150MB 依赖）。原生实现完全够用。

### 建议方案（可另行论证，但要说明理由）

优先级从低风险到高风险：

* **方案 1（首选，风险最低）**：A 类面板彻底去掉液态合成，改为纯绘制。
  这一条很可能就让 90% 的场景实时了 —— 因为侧边栏/走带条/母带卡/工程头正是
  面积最大、最常重绘的那几块。
* **方案 2**：B 类面板用降采样快照（1/4 分辨率、内容变化才重算、缓存）。
* **方案 3（可选，较重）**：`QRhiWidget`（Qt 6.7+，本项目 Qt 6.9.3 可用）
  写 GLSL/HLSL 片元着色器做真正的每帧 GPU 模糊 + 位移。
  只有当 1+2 仍不达标时才上这条。

### 硬性规则

1. **先量后改**：动手前先写一个**能复现当前性能问题**的量化脚本并跑出基线
   （首帧耗时、拖动时每帧耗时、单帧 GUI 阻塞）。改完用**同一个脚本**对比。
   没有基线数字的"变快了"不算证据。
2. **保住现有测试**：`tests/run_all.py` 15 个套件、1081 项断言必须仍然全绿，EXIT=0。
   涉及玻璃的断言在 `tests/test_liquid.py`、`tests/test_design.py`、`tests/test_glass_neutral.py`。
   **这些测试若要改，必须说明"为什么原断言不再成立"，不许为了让测试变绿而改断言。**
3. **只许改这些文件**（其余一律不动，尤其 `app/audio/*`）：
   * `app/widgets/liquid.py`、`app/widgets/glass.py`、`app/widgets/ambient.py`
   * `app/ui/chrome.py`
   * `app/theme.py`（只许加字段，不许改现有令牌语义）
   * 相关测试文件
4. **注释用中文讲「为什么」**，这是本工程一贯风格。
5. **退出码必须单独核对**。本工程出现过「全绿但退出码 `0xC0000409`」的情况 ——
   只看 OK/FAIL 会漏掉。
6. 别用 shell 读 UTF-8 文件（PowerShell 显示乱码）；命令行里传含三引号的
   Python 代码会被 Windows 命令行改坏，补丁脚本请写成文件再执行。

## 三、现状（你接手时的起点）

```
15 个测试套件全绿，1081 项断言，EXIT=0
代码约 23000 行
run.bat 可正常启动
```

玻璃相关的现状：

| 文件 | 作用 | 成本 |
|---|---|---|
| `app/widgets/liquid.py` | SDF 折射引擎（`_sdf_placed` / `_refraction_maps` / `_waviness_field` / `remap_rim_only` / `liquid_fill`） | 12~30ms/面板 |
| `app/widgets/ambient.py` | 背景来源：桌面实拍（`capture_desktop`，把窗口透明化后截屏）+ 预模糊缓存 | 截图会闪一下 |
| `app/widgets/glass.py` | `GlassStyle` / `paint_glass` / `GlassSurface`（含按尺寸缓存的液态合成） | 缓存命中时几乎免费 |
| `app/ui/chrome.py` | 无边框窗口 + DWM 亚克力 + 桌面实拍调度（移动时 80ms 节流） | 节流是妥协 |

**关键：`GlassSurface.LIQUID` 决定一块面板是否走液态路径。**
目前侧边栏 / 工程头 / 母带卡 / 走带条 / 5 条轨道行都开了（共 9 块）。

设计约束（`app/theme.py`，改前必读）：
* `materials` 严格三层：`window_tint` → `panel` → `control`，不透明度必须有序
* `outline`：粗亮轮廓（外侧暗线 + 内侧亮环 + 泛光）
* `finish`：`GLOSS`（光面，默认）/ `FROSTED`（磨砂），可切换
* `labels`：玻璃面上的文字颜色（活力效果，不用纯灰）

```powershell

```

1. **首帧**玻璃合成总耗时：改前 vs 改后（毫秒）

5. **观感是否退化**：给出改前改后的截图对比（`tools/screenshot.py` 可截图），
